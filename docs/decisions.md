# Modal — Decisions

How Modal's design was decided: each decision with when it was made and why, in the order they were made, under the headings of [design.md](design.md). design.md and [grammar.md](grammar.md) say how things are now; where a decision here was later changed, the change is noted beside it, marked as superseded, and the later decision follows it. Kept so the reasons aren't lost, and so a choice can be revisited knowing what was tried.

## Views

**The Tracks view (decided November 2026, for milestone 7; first step built November 2026).** Add a dedicated table of track settings before the outline view. Comparing routing and playback settings across tracks is useful when setting up a song or making an imported MIDI file productive; putting every setting beside the arrangement would consume timeline space and give horizontal movement two different jobs. The arrangement stays focused on time, the outline on sections, and the Tracks view on the song's parts and how they play. Views share the same track settings and remember the musical position when switching.

- Expose what the engine already supports first: number, name, mute, solo, output port, channel, transpose, velocity offset and time offset. Mute and solo go beside the name for easy visual reference. Bank/program setup and playback quantise follow as separate steps. Leave out a whole-track loop toggle, since sections and cycles need a richer looping model.
- Bank and program are numbers initially. Modal does not know each instrument's patch names; reusable instrument program tables can add names later, while keeping numeric addresses underneath. An initial setup is optional and later program events still apply; opening the view does not send a program change. Mid-song playback and live editing need their detailed rules settled before this step is built.
- Playback quantise leaves stored notes in place and has its own grid. Apply it before the millisecond time offset so attack compensation remains effective. Its effect must be visible in the editing views, with bypass for comparison and a deliberate commit operation; note lengths, pedals and live changes still need design.
- Keep track-column definitions independent of view layout, with shared formatting and editing commands. Later, `modalrc` can choose visible columns for the Tracks view and arrangement separately, so mute and solo can appear in both without different state or behaviour. This is an architectural provision; configurable visibility and instrument program tables are not part of the first implementation.

Further agreed in November 2026: `, v t` opens the Tracks view, and its first inspector included note chasing while Arm/Thru wait for GUI recording and MIDI input. Chasing moved into its own column after the first UI trial, below. Keep column order in one ordered list, independent of each column's identity, so it is easy to change in code. Whether users can reorder columns remains open.

Navigation and copying agreed in November 2026: `gt` opens Tracks beside `ga`, `ge` and `gr`, with a count choosing its row (`3gt`); Ctrl-PageDown / Ctrl-PageUp switch tracks, freeing `gt` and leaving `]t` / `[t` for takes. `V` selects track rows, `y` copies settings and all their section content, and Normal-mode `p` / `P` insert copies after / before. Include this in the first implementation, using a distinct register payload and fresh track identities. A copy keeps its routing and mute/solo settings even when that duplicates notes at the same destination; routing or muting the copy is the user's choice. This also provides alternatives and backups without another command. The detailed rules were settled during the first implementation, below.

Freeze is the agreed explicit operation for committing playback transforms and resetting the applied settings as one undo step; its boundary cases and implementation scope remain open. Offset semantics and timing display were agreed separately in November 2026: offsets retain their millisecond or musical meaning through save/load, while display units only change how stored values are read and edited. Accept note fractions with a signed tick adjustment, such as `+1/16-22t` (one sixteenth later, pulled back 22 ticks), as one musical offset. This expresses coarse timing and fine placement together without converting them to milliseconds. The inspector uses note units plus signed fine ticks, with exact bars:beats:ticks readily available; units may be fixed or follow the editing grid. These were built in the first Tracks step; the initial limits and editing details follow below. A possible song-tempo control or fallback also remains open. The current conductor and each section already have a starting tempo, so a fallback needs an explicit inheritance model.

**Initial implementation details (November 2026).** Visual `p` / `P` replace the selected whole tracks, following existing Visual paste. Enter assigns an absolute field value across selected rows, steps are relative to each row, and a batch is all-or-nothing and one undo step. Renaming remains individual. Deletion requires `V` then `d`; Normal-mode event-deletion commands never silently delete a whole track.

Offsets retain the existing ±1000 ms limit; musical offsets allow ±64 whole notes. The table shows their normalised units explicitly. The timing inspector follows the editing grid by default, with fixed fractions through `timingunit`. The initial extra row put separately editable coarse and fine values below the existing exact values. That layout was superseded by the aligned groups after the first UI trial, below. Fine is signed and absolute; stepping a coarse field retains the fine remainder. Existing Enter editing in event-list cells stays available, while `e` opens the inspector.

The first whole-track clipboard requires matching PPQN and section names, order and lengths. This deliberately refuses a layout it cannot map unambiguously; wider mapping between songs is still open. A copy includes per-section meter ownership and editing defaults, but does not duplicate marks. Bank/program setup, playback quantise, Freeze, column configuration and a song-tempo control remain future steps. The current grammar is in grammar.md.

**Tracks UI revised after its first trial (November 2026).** The note inspector's horizontal list separated each coarse/fine pair too widely. It now groups Pitch, Velocity and Off Vel vertically on the left, puts Start above Length with adjacent coarse/fine values in the middle, and groups Bar, exact Position, Length and Ends to the right. Tab follows those groups, with Pitch first. The signed fine values share a column beneath Fine (t), so each pair reads as one time.

Track numbers and numeric settings now align on the right. Musical offsets display a common note fraction plus an exact signed fine remainder, rather than only total ticks; this changes presentation only, and the input spelling is not retained (superseded below, later in November 2026: offsets now stay as typed). Mute and Solo show `-` when off and coloured `M`/`S` buttons when on. Note chasing was initially in the inspector; a status-bar toggle beside Rewind was considered during the trial, then a Chase column after Solo was chosen because Chase belongs to each track. It uses `-`/`C` in the same style, with explanatory inspector text and a palette toggle. Tab/Shift-Tab in a track field editor now commit and move along editable columns. The toggle colours have their own theme roles.

**Tracks, inspector and arrangement refined after use (November 2026).** Several things that worked felt laborious or odd once used.

- Typing `on` or `off` into a button was too much for what's a toggle, so Enter on Mute, Solo or Chase now flips it, and they leave the editors' Tab order. On a selection, every row takes the opposite of the cursor's row, so they end up the same rather than swapping. `M`, `S` and `, t m/s/c` work from any view with a current track; `M` and `S` get single keys because they're wanted while listening, and Chase doesn't because it's rarely changed. A selected row is now one unbroken band, since patches behind each button and gaps between them read as fields that weren't there.
- Rewriting `+1/16-33t` as `+1/32.+27t` was exact but changed the coarse value the user had chosen, so this replaces the earlier decision not to retain the input spelling: a musical offset now keeps its fraction and fine ticks, and plain ticks stay plain, including those in existing files.
- Time jumped about in the note inspector and is about the cursor rather than the note, so it joined the cursor's position in the status line, in every view: the Tracks view has no time cursor of its own, but shows where the cursor will be on changing view. In the inspector, Start, Length and Ends now share a row layout across coarse, fine and exact values, replacing separate Position and Bar fields, with a Note heading matching "No note". B:B:T's colons line up, and beats only take two columns where a meter needs them, so ordinary songs have no extra spacing.
- In the arrangement's inspector, a section's name goes under the Section heading, so Bars and Meter sit where a bar's Bar and Meter are. A bar no longer repeats its section, which the strip shows, and gains Other events, every non-note event rather than only controllers, because all of them shade a bar: the counts always explain its colour.
- "Sections" came between "Trk Name" and the names. Rather than drop it, losing the highlight that shows the cursor is on the strip, the strip moved above the bar numbers. Sections are a bigger unit than bars, the piano roll already has that order, and the track column's heading is now directly above the names, ready for future M, S and C headings.
- A name longer than 15 characters couldn't be seen, so the Name column grows up to 32. Replacing a field's value on the first key stays, since it keeps entering a number quick, but looked the same as editing it, so the whole value is highlighted while the next key would replace it, in the inspector and the event list. Once highlighted it looked selected, so Backspace and Delete now clear it whole. Opening a field used to move its value a cell left, keeping room for a cursor that wasn't there yet, and values on the left of a wide box jumped to its right. A value now stays where it was, and only a cursor past its end takes a cell.
- `M` and `S` on a `V` selection in the Tracks view act as Enter does, since that selection is of whole tracks. They stay out of the other views' Visual modes, where a selection is of events rather than tracks, and the arrangement's could span several tracks in a way that needs thinking through.
- A column can't grow forever, so past 32 characters the Name column only takes room the window has spare, never forcing more sideways scrolling, and the track bar and inspector always give the whole name of the track under the cursor.

**Numeric bank and program setup (November 2026).** Program numbers are 0-127, as the event list already shows them, so one program reads the same everywhere; counting from 1 belongs to particular instruments, so a setting for it waits for the instrument tables rather than being global. A setup is sent even if the track has program changes of its own, because those may have no bank of their own and rely on the setup's. It's sent at the start of playback rather than just before the first note, which is simpler and gives instruments time to load a sound. An edit is sent at once to let a sound be tried, including while stopped for an armed track played from a keyboard; during playback, it holds back where the track's own program change is in force, since the song says what should be playing. Different setups on a shared channel are a warning and not an error, as sharing a channel is legitimate.

- A setup isn't an event: it stays out of the event list and the ruler's signs, since it has no position to move or delete, and out of Freeze, which it survives unchanged. Export is the exception to writing events as stored, or another program would play the wrong sound.
- Thinking about this showed that a track unmuted during playback carried on from its next event, having missed any program or controller change in between. It now catches up as if starting there, as does one becoming audible when a solo is released or being rerouted. Values go whatever the chase setting, which only governs notes. It sends all of them rather than working out which were missed, which is simpler, and only matters where a program sent again could briefly cut a note on a shared channel. Plans carry the song's identity, so that opening another song, with the same track numbers, doesn't look like edits to send.
- Program changes are marked in the piano roll's ruler because nothing there showed why a passage changed sound. The number is dropped where it has no room, as bar numbers are.

**The Tracks table edited in place (November 2026, after use).** Moving editing to the inspector made the eye leave the table, for no gain over the event list's in-cell editing, and so the table now edits every field in its cell. That left room to reconsider what the inspector held: the banks became columns, since it was no longer simpler to keep them apart, and the grid and a new note's length and velocity, shown read-only, became editable columns, as showing a setting that can't be changed there looked odd. They're at the right-hand end, so a narrow window loses them first; the planned per-view column settings could hide them. A port is chosen from a list because a free text box needed the name remembering and accepted anything. A port not found stays, rather than being dropped or refused, since opening a song with an instrument unplugged shouldn't lose its routing; it's dim in the table, as a warning colour on every such row was more than it needs, and explained in the inspector when the cursor is on it.

The tempo showed only in the event list, so the status line now gives it, and the arrangement's ruler marks where it changes; the song's first tempo isn't marked, as every song has one. The ruler's signs for program and tempo changes got a colour of their own, as the label colour was too close to the section names around them. `:event-insert` is a deliberate stop-gap: a way to insert any kind of event, in the song format's forms, until controller lanes and the like have proper ways of their own. The demo song has an example of every kind of event, with a test that keeps it so, because a feature without an example is hard to try.

**Reordering tracks (November 2026).** Requested after use, as a command then the up and down keys until Enter or Escape. `, t o` gives it a place in the hint menu, and Alt-Up and Alt-Down give speed once it's known, moving at once rather than opening the mode. Transport could have stayed working during a move, to listen as tracks go, but keeping it simple and solid was preferred: the mode takes only its own keys.

**Playback quantise (November 2026).** It follows the quantise transform wherever it can, including its function, so that Freeze gives exactly what was heard. One compact column holds the settings, as four would widen the table for something most tracks leave off; typing them all in one line was too much to get right, so they're fields in the inspector, which also suits tweaking one while listening, and an asked-in-turn prompt would only have been a second way to do the same. A `Q` button keeps the settings while off, to compare a track quantised and not; `, T q` compares the whole song. The marks of where notes will be heard can crowd a played part whose notes are all slightly off, so they leave out notes within a few ticks, and can be hidden. Changing a setting while playing needed care: matching each event in the old and new plans by its track, stored tick and message, so a note sent already isn't sent again, rather than treating everything the playhead has passed as played, which would drop notes quantise moves later. A track that can't be quantised, as two notes of a pitch would start together, plays as stored rather than having notes dropped, saying where, as `q` would refuse it.

**Playback quantise after use (November 2026).** On a 1/4 grid most of the demo's tracks played unquantised, since two notes of a pitch quantised onto one line refused the whole track, as `q` refuses. Playback can't usefully refuse, so the note that would move further stays where it's stored instead, which on a busy part keeps the note played on the beat on it, rather than the one after it pulling over. The Tracks table's layout was tightened at the same time: short headings, evenly spaced buttons, a port column sized to its names, and quantise last. The grid and note defaults left it, as they only matter in the piano roll. Up and Down stepping a field wasn't discoverable, so the status line says what a field takes and that they step it while it's edited; the quantise grid steps through triplets as well, as they're common grids to quantise to.

**Selections and the piano roll's moving keys (November 2026, after use).** Nudging a selection moved only the note under the cursor, or nothing, since the moving keys only knew of one note; `t` and `T` shift a selection by grid steps, but nothing moved one in milliseconds. The moving and length keys now take every note a selection takes, refused as a whole as the shift operator is, and the selection goes with them, so nudging and listening can go on; a run of nudges undoes together. A time selection still takes whatever is in it, so moved onto other notes it takes them too.

**Freeze choices and boundary rules (9 November 2026).** Freeze commits playback transforms and resets the applied settings in one undo step, on the whole current track or selected whole rows in Tracks. It initially requires stopped playback, including the stop acknowledgement, so changing the stored identities and times of notes cannot repeat or cut notes already playing. Muted tracks can be frozen; routing, mute/solo, bank/program setup and editing defaults stay settings.

The chooser offers All or one of Transpose, Velocity, Quantise and Time offset, with All selected initially. Up/Down navigate, Enter applies and Escape cancels; unavailable choices are dimmed with their reason and initially skipped by navigation (superseded by Freeze navigation after use, below). This makes committing quantise while retaining velocity or attack-compensation offsets a single choice, without a second interface for arbitrary combinations. Transpose and velocity are independent of timing; quantise must precede time offset. Freezing time alone while quantise is enabled could change the grid lines quantise chooses, so it is refused with "Freeze quantise first, or choose All". All preserves playback order. Quantise and All require global bypass off where an enabled quantise would be committed, so they cannot bake a timing the user has bypassed; transpose and velocity remain independent. Quantise is disabled afterwards but retains its parameters, as its Q button does.

Playback and Freeze share pitch, velocity and quantise rules. Velocity clips as playback does, and release velocity stays unchanged. Quantise commits the playback result, including notes left in place after clashes or the whole track's stored-timing fallback for pedal order, reporting those cases. Refusing an out-of-range pitch rather than dropping it keeps an explicit edit from destroying unheard notes. A start before zero refuses the whole batch rather than clipping only some events and changing their spacing.

Allow events to cross sections, belonging to the section their new starts fall in, and keep notes whole. This preserves what was heard without moving the song's structure; the last section grows as for other edits. Musical offsets shift ticks exactly. Millisecond offsets capture the current tempo map and round starts and ends independently to the nearest tick in elapsed time, ties earlier, so notes crossing tempo changes retain both ends as closely as the stored resolution allows. Refuse a new collision or a positive note collapsing to zero rather than silently merge or lengthen it; existing imported overlaps and zero-length notes survive. Every track in a batch is prepared against the original song before any changes, including growth, and undo restores both events and settings together.

**Freeze availability after the first UI trial (November 2026).** The first trial accepted Freeze's behaviour but found that Enter on All appeared to do nothing when a negative offset would put notes before zero. The list had only previewed setting-level restrictions, leaving event validation until confirmation. It now previews the full batch for each choice and dims every invalid choice with its reason, using the same preparation as confirmation and direct commands. Choices with no active setting are also dimmed, including All when no selected row has work. Zero offsets are inactive even when stored as musical zero, while Q on is still an active setting even if the notes already lie on its grid. A row with nothing to apply can stay unchanged in a batch that changes another row. Preview reasons are cached until the song, bypass or transport state changes, avoiding repeated transformations while drawing the list; confirmation still prepares afresh.

**Freeze navigation after use (November 2026).** Skipping dimmed choices made the initial All selection awkward: it could start on an unavailable item that navigation could never return to, or be stuck there when nothing was available. Up/Down now visit every entry, stopping at the ends of the list. Dimming still shows availability; Enter on a dimmed entry initially reported "Nothing done" with the reason and kept the list open, with no change or undo step (the message rule is superseded below). This replaces the earlier skipping rule and makes the list consistent whether some, all or none of its choices are available.

**Dimmed Freeze entries after further use (November 2026).** The extra refusal message on Enter was redundant with the reason already shown in each dimmed entry, and its display felt inconsistent between inactive transforms and invalid timing. Enter now checks availability first and ignores every dimmed entry, keeping the menu open without a status message, change or undo step. Up/Down still visit all entries. Direct colon commands retain refusal messages, since they have no open list to explain why the operation is unavailable.

## Editing grammar

Editing follows Vim's model: `[count] operator [count] motion-or-object`, with `.` to repeat the last change. Key choices below are proposals; everything is rebindable in the keymap file.

**The grammar made consistent (decided November 2026, for milestone 6's key map review, after a review of the whole grammar).** These replace the earlier decisions below where they differ, which are marked as superseded where they stand; the aim is that what a command takes is predictable, and that a key or object means the same wherever it's offered. Each is marked **Built** or **Decided, to build**.

- **Built.** **An object never reaches beyond the cursor's place:** on a track, that track; on the section strip, every track. On a track (the arrangement's tracks, the piano roll, the event list) `is` is this track's section contents and `it` this track, and `as` and `ie` aren't offered; on the strip, `is` is the section's contents on every track, `as` the section itself, structurally, and `ie` the whole song, every track, and `it` isn't offered. An object not offered says where it is ("ie takes every track: use it on the section strip"). So the strip is for the song's arrangement and the tracks for a track's work, and an operator means the same with an object wherever both are offered (`>as` transposes the section on every track, as `das` takes it out).
- **Built.** **Selecting first is looking first:** an object in Visual mode selects exactly what an operator would take with it, the same tracks and the same notes (`vis` then `d` is `dis`; in the piano roll `vin` selects the note, not the time it takes); `hjkl` in Visual mode go on selecting time, and `V`, `Ctrl-v` and the `, S` group (`, s` until November 2026) widen to more tracks or pitches. As built (after a second review): a selection an object makes from `v`'s remembers the object, its count and where the cursor was, and an operator on it runs as that operator with that object from there, so `vXd` is always `dX`, for every object and count in every view, a test checking each against the other. On the strip, `vis` and `vie` select the sections' events ("events in 2 sections from B on every track"), and `vas` the sections. Moving the cursor, or `V`, `v` or `Ctrl-v`, lets go of the object, the selection being from its anchor to the cursor again, and another object replaces it rather than narrowing it (`vinib` is `vib`); an object that finds nothing leaves the selection as it was, saying why, as its operator would. After `V` or `Ctrl-v`, which chose the rows, an object sets only their time.
- **Built** (with keys for `:bar-delete` and `:bar-insert` in the key map review: a leader group, `, b` "Bars", `, b d` and `, b i`, with counts, room left there for more; `, b i` asks how many bars and in what meter, Enter taking one in the meter there, decided after use). **The selection says what, the command how time closes up:** `D` closes up within each section, whatever made the selection; taking bars out of the whole song is a command of its own (`:bar-delete`, with a key).
- **Built.** **`V` in the piano roll** selects pitch rows over the whole track, as `v` takes every pitch, `ib` or `is` narrowing its time; the status line warns of a whole track. What's shown stays `, S v`'s.
- **Built.** **More motions after an operator:** `0`, `$`, `{` and `}`, each with its end stated exactly (`0` and `$` as `gg` and `G`); `Tab`, `(` and `)` stay moves only, saying why. While an operator waits, the status line says what it will do ("Transpose +3 · this bar · Bass") and what `dd` would take is highlighted; `v` and an object is the way to see a range before acting on it. The shifts are named for what they do: `Alt-l` "Move onto the next grid line", `t` "Shift by a grid step".
- **Built.** **Counts:** a count before an operator with a how far of its own is how far, one after it the range's, taught in the hint menu and shown while typing; a count after `gn` is refused.
- **Built.** **Finds:** `f` and `F` always start a find, and `;` repeats the last the way it went, `Alt-;` the other way (replacing repeating with `f`, which suited Vim's letters better than note names, as after `fC` a `fD` repeated the C). Escape after `dfC`, while a sharp or flat could still follow, undoes the deletion rather than keeping it. As built: `;` and `Alt-;` take a count, and after an operator the range to the note found, as `f` and `F` do; with no find yet they say how to make one. Escape after `dfC` puts the song, the registers and the cursor back as they were, saying "Nothing done", and leaves `.` with the change before.
- **Built.** **Put:** `p` and `P` keep their places, each place binding them to a named command: `put-merge` (`p` on tracks, over what's there), `put-insert` (`P` on tracks, before what's here, which moves on to make room, as Vim's `P` puts text before the cursor), `put-replace` (`p` and `P` in Visual mode), `put-after` and `put-before` (`p` and `P` on the strip); and `put-ending`, with no key, putting the register so it ends at the cursor (for a sweep that must end on a downbeat). After a put the status line says what was put, how, and where. *Built*, and (decided November 2026, after use) **putting at the cursor's pitch:** `Alt-p` and `Alt-P` (`put-merge-at-pitch`, `put-insert-at-pitch`) put as `p` and `P` do, moved by as many semitones as take the pitch the cursor was on when the notes were taken (or, taken outside the piano roll, their lowest; taken in Visual mode, the pitch the selection was started on, the point chosen rather than wherever the cursor stopped, decided after use) to the cursor's, so a riff or a chord's shape goes to another pitch keeping its intervals; refused where a note would go out of range, naming it. In the piano roll only, its cursor being the only one with a pitch; Alt mirrors the put keys, rather than `]p` and `[p`, `]` and `[` being for motions. By semitones; following a key's scale waits for scale lock.
- **Built.** **Questions:** `quantizepedal` (`follow`, `keep` or `ask`, `follow` to begin with) answers `q`'s question in advance, so `q` never asks; the menu's quantise still asks. A question takes only its own answers, `y`, `n` and Escape, showing itself again at any other key rather than taking it for no.
- **Built.** **A command's outcome apart from its message:** whether it did what was asked, was refused or was cancelled, so a warning no longer decides whether a macro stops. As built: a command that doesn't do what was asked says why through `refuse`, which a macro stops at whatever its message's kind ("Nothing to undo" too), and a `:` command's error is a refusal; a message that only reports, a warning among them (a question asked, which the macro's next key answers), doesn't stop one. A find that finds nothing still fails a macro only once its name is done.
- **Decided, to build.** **One current account of the grammar,** in milestone 6's wrap-up, with the dated decisions kept apart from it.

**Modes**

- **Normal:** navigate and apply operators. The default mode.
- **Insert:** type notes and values at the cursor (step entry from the computer keyboard or MIDI keyboard).
- **Visual:** select a range by time, by events, or by rectangle (time × pitch or time × track).
- **Command:** `:` opens a command line for named commands, e.g. `:quantize 1/16 swing=55`, `:tempo 96`, `:w`.

**Motions** (decided October 2026)

Motions in time work the same in every view. In the piano roll the cursor is also on a pitch (see Views).

| Key | Moves to |
| --- | --- |
| `h` / `l` | Previous / next grid step; on a note at the cursor's pitch, off it in one, to the grid step before its start or the first at or after its end (decided October 2026, after use, since stepping through a long note changed nothing shown); but a grid step at a time while selecting in Visual mode, where each step changes what's selected |
| `{` / `}` | The same position one bar earlier / later (`4}` = four bars later) |
| `[b` / `]b` | Previous / next bar line |
| `0` / `$` | Start / last grid step of the current bar |
| `j` / `k` | Next / previous event (event list); down / up a pitch step (piano roll, below) |
| `Tab` / `Shift-Tab` | Next / previous note start at any pitch; in the piano roll the cursor's pitch jumps to that note |
| `(` / `)` | Previous / next chord (a group of notes starting together) |
| `f` + note / `F` + note | Next / previous note of that pitch on this track, e.g. `fE` |
| `[s` / `]s` | Previous / next section start |
| `[m` / `]m` | Previous / next marker |
| `n` / `N` | Next / previous match of the last search (e.g. same pitch, same CC) |
| `gg` / `G` | Start / end of the track; `12G` = bar 12 |
| `ma` / `'a` | Set mark `a` / jump back to it: a time, pitch and track, as in Vim |

- Counts work on every motion: `3l`, `2}`, `2]b`. As in Vim, `0` is a motion only when no count has been started.
- Only some motions are ranges after an operator: those landing on a boundary they name (see Ranges, objects and putting). The others, `{` / `}`, `0` / `$`, `Tab` and `(` / `)`, only move the cursor.
- `w` / `b` (a beat) were dropped (October 2026): a beat is `4l` on a 1/16 grid or `l` on a 1/4 one, and `b` means a bar, as in `]b` and `ib`. `]b` / `[b` replaced `]]` / `[[` at the same time, so a bar has one letter everywhere.
- `Tab` lands exactly on a note's real start, even if it is off the grid. Grid motions from an off-grid position first snap to the next grid line, then step normally.
- Notes starting together are visited low to high by `Tab`; `)` skips the whole chord.
- **Bar motions remember the intended position.** If `}` moves into a shorter bar (e.g. 3/4 after 4/4) and the position would fall beyond its end, the cursor stops at that bar's last grid step but remembers where it wanted to be. Moving on into a longer bar restores the original position, as Vim does with columns across lines of different lengths.
- Bar motions use the bars of the current track (see Per-track meters). `{` / `}` mean "the same position, one bar on" in the arrangement too, so they mean the same thing everywhere.

**Moving in pitch (piano roll)**

| Key | Moves |
| --- | --- |
| `k` / `j` | Up / down one step: a semitone, or a scale step when scale lock is on |
| `K` / `J` | Up / down an octave (always) |
| (to decide) | Up / down a semitone, even when scale lock is on. `Ctrl-k` / `Ctrl-j` were proposed, but Ctrl with `hjkl` moves and scrolls in every view (decided in milestone 3) |
| `gk` / `gj` | To the next note above / below that is sounding at the cursor's time (moving through a chord voicing) |
| `gp` + pitch | Straight to a pitch, e.g. `gp C4 Enter` |

**Scale lock** is a toggle, shown in the status line (key to decide; `, T s` proposed, with the other toggles under `, T`). When it is on, `k` / `j` move by scale steps in the song's key and scale (later, following the chord track if one exists). From a pitch outside the key, `k` / `j` move to the nearest scale tone in that direction. Scale lock also applies to moving notes (`Alt-k` / `Alt-j`) and to step entry.

**Moving and editing notes**

The same motions move notes when combined with Alt:

| Key | Effect |
| --- | --- |
| `Alt-k` / `Alt-j` | Move the current note (or selection) up / down one step (a semitone or a scale step, per scale lock) |
| `Alt-K` / `Alt-J` | Move up / down an octave |
| `Alt-l` / `Alt-h` | Move later / earlier to the next grid step |
| `Alt-L` / `Alt-H` | Nudge later / earlier by the `nudge` setting (5 ms) |
| `Alt-}` / `Alt-{` | Move later / earlier by a bar |
| `=` / `-` | Lengthen / shorten the current note to the next grid step |
| `+` / `_` | Lengthen / shorten it by a nudge |
| `o` | Create a note at the cursor, with the track's default note (its length and velocity), without entering Insert mode |
| `O` | Create one and move the cursor on, to its end or (with `gridadvance`, `, T a`) the next grid step; `8O` creates eight in a row |
| `x` | Delete the note under the cursor |

Alt and Alt-Shift with the arrow keys do the same as with `h` `j` `k` `l` (as built). Counts apply: `3Alt-l` moves three grid steps later. Operators (`>ib`, `t]b`, etc.) remain for larger ranges.

**Editing notes, decided for milestone 5 (step 4c).**
- **To the grid.** `Alt-h` / `Alt-l` move a note's start to the grid steps counted from each bar line, as `h` / `l` move the cursor, so a note off the grid lands on it at the first press: moving by a grid's distance while staying off it would make no sense. `=` / `-` move its end the same way, to the next or previous grid step, and `-` doesn't shorten a note below one grid step (a note already shorter isn't made shorter still).
- **Nudging.** For tweaking a played, unquantised part or a groove, `Alt-H` / `Alt-L` nudge a note earlier or later, and `+` / `_` lengthen or shorten it, by the `nudge` setting: milliseconds rather than ticks or a note fraction, since timing feel is heard in milliseconds at any tempo, as `chordwindow` is (5 ms by default, about the least a shift is felt; a tick is far too fine, half a millisecond at 960 PPQN and 120 BPM). Counts multiply it. The Shift keys are the fine forms of the grid keys beside them, so in the piano roll `+` is no longer another `=`. A nudge never shortens a note below one nudge, and moves at least a tick, however short it is at the tempo there (as built). In the event list and on the section strip, `+` and `_` step as `=` and `-` do; the commands are `note-lengthen-fine` / `note-shorten-fine` (the event list's `field-increase-fine` / `field-decrease-fine`) and `move-left-fine` / `move-right-fine`.
- **Collisions.** Moving, lengthening, adding with `o` or putting with `p` onto a note of the same pitch is refused, naming that note, as in the event list; `o` on a note says there's one there. Moving before the song's start fails, as motions do. Counts on `o` wait, since a run of notes needs its spacing thought about.
- **Adding and moving on (decided October 2026).** `O` adds the default note and moves the cursor on, for entering a melody quickly, while `o` stays put for chords: a key of its own rather than a toggle, so there's no hidden state to forget, and both are a key away. It moves on by the note's length, so notes join end to end, or with the `gridadvance` setting (off by default; `, T a` turns it on and off) to the next grid step, for legato notes a little longer than the grid. That spacing settles counts: `8O` adds eight in a row, one undo step, as far as the song's end or a note in the way, which is named; with `gridadvance` and notes longer than a step, the same pitch runs into itself, so it suits melodies, whose pitch changes. Step entry (milestone 8) moves on as it enters, a toggle of its own there if wanted.
- **Operators.** (Revised October 2026, before it was pushed: `dd` and `yy` take the cursor's bar, and `x` and `Y` the note; see Ranges, objects and putting.) `x` and `dd` delete the current note, `yy` and `Y` yank it. `d` and `y` with a motion in time take the notes starting in that time at every pitch, as the arrangement's take its area, but only notes, since they're all the piano roll shows (as built, leaving the track's other events alone); with a pitch motion (`dj`) they wait for Visual blocks (milestone 6). `p` puts the register at the cursor's time, at the notes' own pitches, and a register of several tracks from the arrangement onto this track and those after it, as there. Each edit is one undo step, and undo brings the cursor back to the note; steps of a note's velocity with `Ctrl-A` / `Ctrl-X` one after another undo together, as the grid's do (as built).

**Grid**

- Values: straight 1/1 to 1/64; triplets (1/4T, 1/8T, 1/16T, …); dotted values; any tuplet from the command line, e.g. `:grid 1/16 5:4`.
- Stored **per track** and saved in the song. Shown in the piano roll's bar, e.g. `Grid: 1/8t`. A new track's is 1/16.
- The grid drives `h` / `l` movement, and `q` quantise unless a value is given (`:quantize 1/16`).

| Key | Effect |
| --- | --- |
| `zh` / `zl` (or `z` with Left / Right) | Finer / coarser grid, halving or doubling it and keeping triplets (1/8T to 1/4T): the steps narrower to the left, wider to the right (decided October 2026, after trying them the other way) |
| `Ctrl-t` | Toggle triplet (1/8 ↔ 1/8T) |
| `:grid …` | Set any grid exactly |

**Default note length**

An independent setting for the length of new notes, after Sequencer Plus Gold's default note length.

- **Linked to the grid by default:** the length follows the grid, and the piano roll's bar shows `Note: grid v100`.
- Changing the length unlinks it; it then stays fixed whatever the grid does, and the bar shows it, e.g. `Grid: 1/16  Note: 1/8t v100`. `:len grid`, or the leader menu, links it again.
- With a velocity, the two making the track's **default note** (decided for milestone 5), which `o` adds.
- Stored per track and saved in the song.
- Used by `o`, step entry (from a MIDI keyboard or the computer keyboard) and inserted rests. Not used by recording: played notes keep their real lengths.

| Key | Effect |
| --- | --- |
| `, n` | Take the current note's length and velocity as the default note |
| `:len 1/8` / `:len grid` | Set the default length, or link it to the grid again |
| `, l` + keys | Set it directly from the leader menu (milestone 6): `4` quarter, `8` eighth, `6` sixteenth, then `t` triplet or `.` dotted (e.g. `, l 8 t` = 1/8T) |

`+` / `_` were to step the default length through the common lengths. They were dropped (decided for milestone 5): a length is better judged from a note you can see, and `+` steps the field under the cursor in the event list; in the piano roll it lengthens the current note by a nudge (see Moving and editing notes).

**Text objects** (used after an operator, `i` = inner, `a` = around)

- `ib` / `ab`: this bar's contents / this bar as time, which `dab` takes out, closing the gap; `in`: this note (in the event list, this event); `is`: this section's contents; `as`: this section as a structural unit (its contents, length, tempo and meters); `ic`: this chord (notes starting together); `it`: this whole track; `gn`: the next search match (see Search). `is` and `as` replace the earlier "phrase between markers" (`ip`), since markers are now bookmarks.
- Read as Vim's help reads `aw`, "a word": `dib` is "delete inner bar", its contents, and `dab` "delete a bar", the bar itself (decided October 2026).
- **The other objects (decided October 2026, for milestone 6).** A count after each takes more of them (`d2is`, `>3ic`, `q3it`).
  - **`is`** is the cursor's section on the cursor's track, as `ib` is its bar, in every view; on the section strip, the section's events on every track, so `qis` there quantises the whole section.
  - **`as`** is the section itself, on every track, since sections are whole bars on every track: `das` takes it out of the song and `yas` yanks it as a section, from any view, as `x` and `Y` do on the strip. *(Superseded November 2026: `as` is offered only on the section strip; on a track it's refused, saying so; see "The grammar made consistent" under Editing grammar.)* To the operators that change events in place (`>`, `t`, `q`, `^`, `~`) it's `is`, as `ab` is `ib` to them, and their hint menu leaves it out.
  - **`ic`** is the chord holding the note under the cursor: the notes starting within `chordwindow` of it, as `(` and `)` take chords, in the piano roll and the event list. With no note under the cursor, and in the arrangement, it's refused, as `in` is.
  - **`it`** is the track's events, not the track: `dit` empties it, keeping the track. In the arrangement a count takes more tracks from the cursor's; in the piano roll, which shows only notes, it takes the notes, as its other ranges do; it's refused on the conductor's list.
  - **As built** *(the tracks' `das` and `yas` superseded November 2026, as above)*: `das` and `yas` from the tracks put the sections in the register as the strip's `x` and `Y` do ("Verse yanked; p on the section strip puts it back"), refusing to take a song's last section. The undo titles name the sections and tracks: "Delete Verse of Bass", "Delete Verse on every track", "Delete all of Bass". In the event list, `ic` takes the chord's notes only, not a controller among them.
  - **On the section strip,** the operators other than `d` and `y` take only `is` and `as`, refusing anything else, pointing to `is`.

**Operators**

| Key | Operation |
| --- | --- |
| `d` / `y` | Delete / yank |
| `p` / `P` | Put over what's there / put in, moving what's after it later |
| `>` / `<` | Transpose up / down a semitone (a count before the operator = semitones) |
| `q` | Quantise notes' starts to the current grid |
| `^` | Set or scale velocity (prompts for a value, a change or a %: `^ib 80`, `^ic +10`, `^ib 80%`) |
| `!` | Transform: opens the transform hint menu for the range (see MIDI transforms) |
| `t` / `T` | Shift later / earlier by the grid step |
| `~` | Humanise (small random time and velocity changes) |
| `c` | Change: delete the range and start Insert mode there (milestone 8) |

Examples: `d2]b` deletes from the cursor to the second bar line on, `>ib` transposes this bar up a semitone, `5.` repeats the last change with a count of five in place of its own (after `>ib`, `5.` transposes five bars).

- **The velocity operator is `^` (decided October 2026),** an upside-down `v` and the marcato accent sign, since `v` is Visual mode. Vim's `^` (first non-blank) has no use in Modal. `%` is kept for something else.
- **`!` is the general transform operator (decided October 2026),** with an imperative feel: `!` and a motion open the transform menu for that range. Velocity, the most common transform, keeps its own key.
- **The other operators, as built in milestone 6 (decided October 2026).** `>` `<` `t` `T` `q` `^` `~` take the same ranges and objects as `d` and `y`, in every view, and each change is one undo step:
  - **Counts.** A count before the operator is how far (`3>ib` up three semitones, `2t]b` two grid steps), and one after it the range's (`>3ib` three bars up one), rather than the two multiplying as they do for `d` and `y`. Those with no how far of their own, `q`, `^`, `~` and `!` with the transforms, multiply them as `d` and `y` do, so `2qq` quantises this bar and the next and `2!!` transforms them (decided November 2026, on trying `!!`). Doubled (`>>`, `qq`, `^^`, `tt`, `~~`), an operator takes the cursor's bar, as `dd` does. To them `ab` is `ib`, since they don't take time out, so the hint menu leaves it out.
  - **`T` shifts earlier,** paired with `t` as `P` is with `p`.
  - **What each acts on.** Transposing, velocity, quantising and humanising change notes only, in every view, since quantising a controller's fade would wreck it. Shifting moves every event in the range in the arrangement and the event list, so pedalling and controllers stay with their notes; in the piano roll, which shows only notes, it moves the notes. The grid is each track's own.
  - **Refused, whole.** A change that would take a note past G9 or below C-1, an event before the song's start or past its end, or a note onto another of its pitch, is refused, naming the note, rather than made in part. Where a change moves times (shifting, quantising, humanising), a note run into the next of its pitch ends where that one starts instead, as played legato and then quantised notes need, since a key can't be replayed while it's held; two at the same start are still refused.
  - **Quantising** moves notes' starts fully onto the grid, keeping their lengths. Strength, swing and quantising ends or lengths alone (as Sequencer Plus Gold had) are for `:quantize`, with the MIDI transforms.
  - **Pedalling follows quantised notes, if wanted.** When the range has sustain, sostenuto or soft pedal events (CC 64, 66, 67), `q` asks "Move the pedalling with its notes? (y/n)". With `y`, each pedal event moves as far as the latest note at or before it moved, a chord's notes moving as one, so a pedal pressed just after a chord stays just after it, and a lift just before the next chord stays with the chord it ends; one before any note in the range stays put. If a pedal would move past the next of its pedal, the change is refused, saying where. A setting could answer the question in advance later (`quantizepedal`), if asking proves tiresome. *(Built November 2026: `quantizepedal`, `follow` to begin with, so `q` doesn't ask; see "The grammar made consistent" under Editing grammar.)*
  - **`^`** asks at the prompt, its label in place of the `:` ("Velocity of 2 notes in Bass (80, +10, 80%): "), for a value from 1 to 127, a change (`+10`, `-10`) or a percentage (`80%`), velocities kept between 1 and 127. The answer stays out of the `:` prompt's history, and Tab doesn't complete it.
  - **`~`** moves each note's start by up to `humanizetime` (10 ms) either way, at its own tempo, and its velocity by up to `humanizevel` (8) either way.
  - **Not on the section strip** at first: its sections' contents across every track came with the objects `is` and `as`, which the operators take there.
  - **`c` is kept for change,** as in Vim: delete the range and start Insert mode (step entry) there, when Insert mode comes in milestone 8 (`cib` to play a new part into this bar). Changing a channel is the track's (`:channel`, the inspector); moving a range to another track is `d` and `p` for now, perhaps later a command with no key, `:move-to TRACK`.

**Ranges, objects and putting (decided October 2026, in milestone 5).** Every range an operator takes says what it is: either from the cursor to a boundary its key names, or an object, a whole thing at the cursor named by its letter. Where they differ, this replaces the notes on operators in the event list (milestone 4), the arrangement, the piano roll and the section strip, which say what was built at the time.

- **Ranges.** `]b` / `[b` (bar lines), `]s` / `[s` (sections), `]m` / `[m` (markers), `gg` / `G` (the song's start and end), `h` / `l` (grid steps in the piano roll, bars in the arrangement, sections on the strip) and `j` / `k` (events in the event list, tracks in the arrangement), with counts. A range runs from the cursor up to the boundary, not taking what starts there: `d]b` is the rest of the bar, and `d[b` from the bar line before up to the cursor (from a bar line, the whole bar before). `gg` and `G` take what's at the ends too.
- **Moving only.** `{` / `}` go a bar's length, not to a boundary; `0` / `$` end at a bar, a field or a section depending on the view; notes and chords are things rather than boundaries, so `Tab` and `(` / `)` stay quick keys for getting about while `in` and `ic` take them. In the arrangement, `Tab` / `Shift-Tab` go past empty bars to the next or previous bar where an event of the cursor's track starts, controllers too, as Sequencer Plus Gold's did (decided October 2026), a count going that many on, and say so when there's none. After an operator these say so, pointing to the ranges ("`}` moves the cursor; for a range use `]b` or `]s`").
- **Boundaries and things.** Bar lines, sections and markers divide time, and have bracket motions; notes and chords sit in time, and have objects; bars and sections are both. A letter means the same in every form: `b` is a bar in `]b` and `ib`, `s` a section in `]s` and `is`.
- **Contents and time.** `dib` deletes the bar's events and leaves silence; `dab` takes the bar out and moves the rest of the section up, leaving silence at the section's end (see How far ripple reaches); counts take more bars (`3dab`). On a track the bar is that track's, in its own meter. Since `dab` edits time, in the piano roll it takes every event there, controllers too, where `dib` takes the notes, as the piano roll's other ranges do. The event list, which isn't for editing time, has no `ab`.
- **The cursor's bar.** `dd` and `yy` are `dib` and `yib` in every view (`3dd` three bars): rows of the event list and notes in the piano roll are how events are drawn, not the song's structure, so the bar is the unit. `x` and `Y` delete and yank the note or event under the cursor, as `din` and `yin` do; in the arrangement, with no single note at the cursor, they say so. On the section strip, where the cursor is a section, `x` and `Y` delete and yank the section, and `dd` and `yy` are refused, pointing to them.
- **Putting.** `p` lays the register over what's there, merging (which has real uses, such as layering a part; `dib` first clears the bar to replace it), and `P` puts it in, moving what's after it in the section later by its length (the bars or span it was taken from, or a note's length) and asking first if the section must grow. The key decides which, never how the register was filled, which may be forgotten by then. A register taken as bars (`ib`, `ab`, `dd`, or the arrangement's bars) keeps to bars: `p` lays it over the cursor's bar from its start, and `P` puts it in before the cursor's bar, wherever the cursor is in it; so after this bar is `]bP` (`lP` in the arrangement). Anything else is put at the cursor. The event list has `p` but not `P`.
- **Every track.** The strip is for sections, so it doesn't take bars across the tracks. Taking a bar out of every track, which shortens the section, is a Visual selection across all the tracks (milestone 6), or meanwhile `:bar-delete` (with a count for more bars) at the cursor's bar, in the conductor's bars, with the tempo and meter changes and markers in it. It's refused where the bar's start or end falls inside a bar of a track with its own meter, naming the track ("Bass's bars don't line up with this one; cut it on each track instead"); meters that line up, such as 6/8 under 3/4, are fine. `:bar-insert` (with a count for more bars, and optionally a meter, `:bar-insert 2 3/4`) puts empty bars in before the cursor's bar on every track, as `P` puts in before, lengthening the section; the bars take the meter there unless one is given, which then holds for the new bars alone, the meter after them going on as before. Tracks with their own meter take them only if their length is whole bars there, or it's refused in the same way. As built (October 2026): `:bar-delete` splits the bars out as sections of their own, removes them and joins what's left of the section they were in, so it's `das` on bars, the section staying one; what went is kept in the register as sections, named "From" and the section they came from ("From Verse", decided October 2026, so they're told apart from the section itself, and numbered when put back again, "From Verse (2)"), while whole sections yanked on the strip keep their names, being copies of them, so `p` on the strip puts them back as a section, and putting them into the middle of another section waits for Visual mode. `:bar-insert` is the same in reverse, the empty bars going into the cursor's section, before its first bar when it's at its start. Each is one undo step; the messages are "Bass's bars don't line up with bar 2; delete them on each track instead" and "…put them in on each track instead".
- **No capitals for time.** `D` is unbound: Shift doesn't mean "in time", and Vim's `D`, to the end of the line, has no one end here. `P` is `p`'s partner, putting in as Vim's puts before; `Y` is `x`'s, for the note.
- **Taught by the hint menu.** After an operator, the hint menu lists the ranges and objects with what each would do in the current view (see Leader key and hint menu).

**In milestone 4 (decided for milestone 4).** The operators `d`, `y` and `p` work over the motions, with counts, on rows of the event list as Vim's do on lines (`d}` deletes from this event up to the one `}` lands on); `dd` deletes the event under the cursor (`3dd` it and the next two) and `yy` yanks it; `x` deletes the event and `o` adds a note at the cursor. *(Revised October 2026: `dd` and `yy` take the cursor's bar's events, and `x` and `Y` the event; see Ranges, objects and putting.)* There is one unnamed register, and linear undo and redo. Visual mode, named registers, `.`, marks, `f` / `F` and searches come in milestone 6. (Revised in milestone 5: see Ranges, objects and putting.)

**Sections in milestone 4 (decided October 2026).** The section model and the song format, the flattened timeline, SMF import and export with sections, the section shown in the event list (with markers, dimmed) and in the status line, `]s` / `[s`, `:section NAME` to split at the cursor's bar line (with the warning when a bar is split). As built: `:section` works in every view, the bar line being that of the cursor's bar in the view's own bars (the conductor's in its list, a track's own where it has its own meter); with no name, the new section is called `Section` and the next number, so a new song's sections go Section 1, Section 2; a name another section has is numbered; at a section's start, or past the song's end, it's refused; and when the bar line falls inside a bar of the conductor (and the tracks following it) or of a track with its own meter, the new section still starts there, the bar it cuts ending short as a remainder bar, and the message says which ("Bridge starts at 2:1:000; this cuts a bar short in Lead"). Each split is one undo step. `D` / `P`, rippling to the end of the section with the question when an insert would overflow it, come in milestone 5 with the time-based views (decided in milestone 4): the event list is for exact tweaking of events, not editing in time, and its cursor is always on an event, so time spans there would do odd things or need workarounds. The section strip comes with the views in milestone 5, section operations with the full grammar in milestone 6, the outline view in milestone 7, and looping, takes and cueing in milestone 8.

**Registers, macros and undo**

- Named registers (`"a` to `"z`) hold phrases; pasting fits them to the current grid position.
- Macros record and replay key sequences, as in Vim but on `Q` (`Qa` … `Q`, `@a`), since `q` is quantise.
- Linear undo/redo in version 1 (`u`, `Ctrl-R`); an undo tree later.
- **Decided for milestone 6 (October 2026).**
  - **`.`** repeats the last change with its range or object (an operator, `x`, `p`, `o`, a field step, a transform), `^` with the same answer, without asking again; a count before it replaces the change's. After a Visual operator it takes as much from the cursor: as many bars, as long a time, as many rows. As built: the keys typed from Normal mode until it's idle again (no keys waiting, no operator, no prompt or Visual mode) are the change, if the song changed meanwhile, undo and redo apart; `.` replays them, as one undo step, so a selection's motions, `^`'s answer and a field's value come with them.
  - **Named registers** `"a` to `"z`: `"ayy`, `"ap`; `"A` adds to a, what's added going after what it holds, as laid end to end, so bars from different places gather into one phrase (sections on the strip the same way). `:registers` lists what each holds, one a line over the view, each name right-aligned in the hint menu's key colour and the colons in one column, the next key closing it and doing nothing else (decided after use; `:macros` the same). For the session, for now. As built: `"` takes the letter after it, as marks, macros and `f` will take theirs (Escape giving it up, anything not a letter refused); the register named holds for the next command, a put putting from it ("Register a is empty" if it is), a yank or delete filling it or with a capital adding to it, the unnamed register getting what's taken either way, as in Vim. Laid end to end means after the span the register's contents took, rests kept, or for the event list's rows, which have no span, at the last event's time. Vim's other registers, `"0` (the last yank), `"_` (deleting without touching any) and `"+` (the system clipboard), are to revisit later (noted October 2026).
  - **Macros** on `Q`: `Qa` records into macro a until `Q`, `@a` plays it, `@@` the last again, `3@a` three times, each run one undo step; "recording @a" on the status line meanwhile. Kept apart from the registers, a register holding events and a macro keys, and kept between sessions in the remembered state, being the user's tools rather than the song's. As built (decided October 2026): the status line says "recording @a, Q ends it", the key from the binding; every key typed meanwhile is kept as typed, at the `:` prompt and in the palette too, Escape among them, but for the binding that ends it, and `QA` adds to a. The keys are replayed through the same path as typed keys, any left waiting for a longer binding at the end running as when their time is up. A command failing stops the macro and any playing it, as in Vim, what was done staying to undo or carry on from: a refusal (a warning, until November 2026, when a command's outcome was set apart from its message), keys that do nothing here (or are no range after an operator), a command for another view, or a motion that can't move (`h` at the song's start), so `100@a` ends at the last note or the song's edge. A macro may play macros, itself among them, and may be played while one is recording (the macro as it was); they stop 20 deep with a warning. `.` after `@a` repeats the `@a`, and `.` in a macro the changes made in it. `:macros` lists them as `:registers` does, in key notation, lines too long for the window cut short. They're saved in the remembered file as `macro a KEYS`. `"a` and the other commands taking a letter are part of the change `.` repeats.
  - **Marks:** `ma` marks the cursor's place, its track, time and pitch, saved in the song (unlike Vim's, since they're places in it); `'a` goes there, and after an operator takes the range to it (`d'a`); `''` goes back to where the cursor was before the last jump, stopping playback in place counting as one. `m Space` stays the play-from marker. Settled for building (decided October 2026): letters a to z only, since what Vim's capital marks across files would mean in Modal is unclear, even once several songs can be open (milestone 7); a mark is kept in the section it's in, as markers are, so it goes where the section goes, those in bars or sections taken out going with them, sections put in bringing none (a letter marks one place), and removing a track removes its marks; in the song file a section's `mark a 3:1:0 track=2 pitch=C3` lines, the format staying at version 1 while Modal is experimental; setting one is an undo step, so a mark moved by accident can be put back. A mark set in the arrangement is at the cursor's bar's start and one set in the event list at its row's time, neither with a pitch, which only the piano roll's have: going to one without a pitch in the piano roll keeps the cursor's pitch, and the piano roll shows it in the ruler alone. `''` remembers one place; a jump list (Vim's `Ctrl-o` / `Ctrl-i`) is for later. - **Undo steps (decided for milestone 4).** Each operator, field edit or command is one undo step; so are a whole recording pass (milestone 8) and a whole macro run (milestone 6), and `.` repeats a change as one step.
- **Undo history (decided in milestone 4).** Every change to the song is an undo step, the track settings, mute, solo and renames included, since they're saved in the file; an edit that leaves the song as it was is none. Moving and scrolling aren't steps, so `u` never has to wade through navigation: instead each step records where it was made, the cursor's track and position and the view's state (scroll and zoom, or page), and undo and redo go back there, so stepping through the history shows each change where it was made. A view scrolls further only if the change reaches beyond that. Undoing back to the version last saved or loaded makes the song unmodified again. `undolevels` (1,000 by default) is how many steps can be undone; what can be redone doesn't count. Past versions are kept without their flattened timeline, which is rebuilt on undo, so a step costs only what it changed (typically one track's part of one section), and a thousand steps take a few tens of MB at most. Each step has a title that reads on its own, as in an undo list one day ("Delete 3 events in Bass"), shown as "Undid: …", and its time. The core's `Document` holds the song, its file and the history, and calls a listener after every change, which hands the engine each new snapshot.

**Notes crossing a range's edges**

- **By default, a range owns the notes that start inside it.** Copy, delete and transforms act on those notes whole, including any part that sustains past the range end. Notes that started before the range and are still sounding are left alone. Nothing is cropped, so a held pad chord stays one chord.
- **A cut-at-edges mode splits notes at the boundaries.** In Visual mode, `|` toggles cut-at-edges (shown in the status line and by the edge markers changing). Operators then split notes crossing a range edge at the boundary first, and affect only the inside parts. Deleting bars 9–10 from a sustained chord leaves the chord sounding up to bar 9 and from bar 11. Without a Visual selection, `|` before an operator does the same for that one operation (`|d]b`).
- **The edges are visible.** In Visual mode, notes that cross an edge are drawn with a marker, so it's clear which ones will be taken whole and which left behind.
- **As built in milestone 6 (decided October 2026).** `|` toggles cutting for the selection, off again for the next one, shown in the status line ("cutting at the edges"); before an operator in Normal mode it holds for that one, shown as pending (`|d]b`, `|dd`). In the arrangement and the piano roll; in the event list, whose ranges are rows, and on the strip, whose edges cut no notes, it's refused. A cut note's part before the edge is released at the usual velocity (64), the part after keeping the note's own. `d`, `D` and `p` cut, then act, as one undo step under the operator's name; `y` yanks the parts inside, leaving the song as it is; the other operators cut in their own change, so `^` cancelled at its prompt cuts nothing. In the piano roll the part of a note outside a cutting selection is dimmed and its part inside stands out, and either way the part of a note it takes whole that sounds on past its end is dimmed.

**Leaving silence or closing the gap**

Both are needed. Closing the gap is taking time out, so it goes with the objects taken as time (see Ranges, objects and putting):

- `dib` deletes and leaves silence; `dab` deletes and closes the gap, moving everything after the bar earlier on the track.
- `p` puts material over what's there (merging); `P` puts it in, moving everything after the insertion point later.
- First, uppercase meant "and shift the timeline", with `D` closing the gap over any motion; it was replaced in October 2026, since ranges like `D}` didn't say what they took, and `D` is unbound. `dG` deletes from the cursor to the end of the track.

**How far ripple reaches (decided October 2026)**

- **Ripple stays inside the section.** On one track, `dab` moves the material after the bar earlier only up to the end of the current section, and `P` moves it later only up to there. The section keeps its length, so `dab` leaves silence at the end of the section on that track; other sections and other tracks are unchanged. Not the view, since an edit's result must never depend on zoom or page size; and not the whole track, which would shift every later section of that track against the other tracks and move notes across section boundaries. The section is the musical unit: tightening or extending a phrase within it keeps the rest of the song aligned.
- **Wider scopes are explicit.** A whole section on every track (from the section strip, or an arrangement selection covering every track) removes or inserts time across all tracks, so the section shortens or lengthens and the rest of the song moves with it, a structural edit like deleting or inserting bars; `:bar-delete` does it for bars (see Ranges, objects and putting). `:ripple track` ripples to the end of the track, for rare cases, never by default.
- **Ripple works on whole spans of time,** not single notes: bars (`dab`), sections, or a Visual time range. On a single note, especially one in a chord, closing a gap has no clear meaning, so `x` deletes the note and leaves its time.
- **An insert that would overflow the section** never pushes notes into the next section silently. The status line asks (yes / no) whether to grow the section by whole bars, on every track, to make room; the new bars on other tracks are empty. Declining cancels the insert.
- Each ripple, including any growth of the section it causes, is one undo step.
- **In milestone 5 (October 2026).** `D` over a motion was built first, then, before it was pushed, replaced by `dab` and `P` (see Ranges, objects and putting), which keep its workings: a span running past the section's end stops at it; `P` makes room for the register's length, so `yy` of a bar then `P` makes room for exactly a bar; and when `P` would push events past the section's end, the status line asks whether to lengthen the section by the whole bars needed, `y` for yes and anything else for no ("Nothing done"), the growing and the insert being one undo step.

**Visual modes (decided October 2026)**

The three Visual modes, with the piano roll's two dimensions of time and pitch:

| Key | Selects | Example |
| --- | --- | --- |
| `v` | A time range, every pitch within it | Everything in bars 3–4 |
| `V` | Whole rows | Every kick drum on the page |
| `Ctrl-v` | A box of time × pitch (or time × track) | The top notes of the chords in bars 3–4 |

- `V` means whole rows of the current view everywhere: whole events in the event list, whole tracks in the arrangement, whole pitch rows in the piano roll, and a run of sections on the section strip.
- In the piano roll, `V` selects every note at the cursor's pitch on the current page *(superseded November 2026: across the whole track; see "The grammar made consistent" under Editing grammar)*; `j` / `k` add further pitch rows (kick and snare together). A text object after `V` sets the time range: `V` then `as` takes the rows across the whole section, `V` then `it` across the whole track. `:select pitch C1 in section` (or `in page`, `in track`) does the same from the command line or palette, and takes drum-map names (`:select pitch kick in track`).
- Typical uses: boost the kick drum with `V` then `+10` or `:vel lift 20%`; move every kick to another sound with `V`, then `Alt-j` / `Alt-k` with scale lock off, or by typing the new note in the inspector.

In the event list, `v` and `V` are rows of events, and `Ctrl-v` is refused. On the section strip, a run of sections.

  - **`:` commands on a selection (decided October 2026, replacing `:marker-to-section-all`):** from Visual mode the prompt is labelled with what's selected in place of the `:` ("bars 2–9 on every track: "), and a command that takes a range (`range` in its description) acts on the selection, others saying they don't. `:marker-to-section` on a selection turns every marker in it, asking about those off a bar line as `-all` did, the cursor going back where it was (so `vie:marker-to-section` is the old `-all`); `:bar-delete` deletes the selection's bars on every track, refused where they aren't the conductor's bar lines. Commands that compose this way, rather than special cases. The selection ends as the line runs, since a run like `:marker-to-section`'s moves the cursor from marker to marker.
  - **As built:** the workspace keeps where the selection started (`Selection`, in view.hpp, with the view's own index where a time can't tell rows apart) and each view turns that and its cursor into what it takes, which the operators take as the motion `visual`. Visual mode's keys are its own (`vmap`: `o`, `D`), then the objects, then Normal mode's, but for keys that start an object's (`i`, `a`).

**Search (decided October 2026)**

As in Vim, search matches are a layer separate from the selection.

- **Matches** are the result of the last search, drawn in their own style (an outline, say), distinct from the selection's fill, so both can be seen at once. They stay highlighted until `:noh` (or a key, to decide), and the status line shows the position among them, e.g. `match 3/24`.
- **Searching:** `*` / `#` search forwards / backwards for the current note's pitch; `/` and a query searches; `n` / `N` go to the next / previous match. Search covers the current track in the piano roll and event list; across tracks in the arrangement can come later.
- **Queries (to begin with):** a pitch (`/C1`, `/F#3`) or a drum-map name (`/kick`); conditions (`/C1 vel<60` for quiet kicks, `/vel>110`, `/len<1/32`); event types (`/cc64` for sustain, `/cc1`, `/bend`). Interval and rhythm patterns can come later (see Ideas: musical search and replace).
- **All at once:** `g/` makes the matches on the current page the selection, and `:select matches in section` (or `in track`) does so over a wider range; then any operator or transform applies. (The keys were settled otherwise: see below.)
- **One at a time:** `gn` is a text object for the next match. An operator with `gn` changes the next match and moves to it; `.` repeats the change on the following match, and `n` skips one. For example, `^gn +15` accents the next kick, then `.` on each kick to accent and `n` past the ones to leave.
- **Settled for milestone 6 (decided November 2026).**
  - **Selecting matches** is under the leader, in a group of its own for selecting, `, s` (rather than `g/`, which only means something to those who know Vim's `:g`, and since it's done less often than the keys without the leader): `, s b`, `, s s`, `, s t` and `, s v` select the bar, the section, the track and what's visible, and the capital of each selects only the matches in it (`, s B`, `, s S`, `, s T`, `, s V`; the bar's added after use), so each pair is listed together in the hint menu; in Visual mode `, s m` narrows the selection to the matches in it; `, s c` clears the matches. So there's no default reach to choose: it's chosen by the key. A selection of matches is the selection's area with a filter, the query, so operators take only the events in it that match, and `o` and `gv` go on working. As built: what's visible is the view's span of time, or in the event list its rows; in the arrangement the area is on every track, as `v`'s is, so the matches are taken there on every track, not just the cursor's, which is all a search looks at. Only the matching notes and rows are drawn as selected, and the status line adds "only the matches". `D` and `p` are refused on a selection of matches, since they take its time ("D takes out the selection's time, not its matches"); `d` and `y` take the matches as a register holds them, from the selection's start.
  - **`gn`, as built (decided November 2026):** after an operator, the match at the cursor, or the next if it's on none, the cursor going to it: in the piano roll the note there, in the event list the row, in the arrangement the matches in the cursor's bar. After a change (after `^`'s answer, for `^`) the cursor goes on to the next match, so the one `.` will change next is seen first, and `n` skips it; unlike Vim, whose cursor stays at the change (decided November 2026, on trying it). Where the last change by `gn` was is kept, so `.` doesn't change it again when it's the only match left. A yank, which `.` doesn't repeat, stays where it is. Being seldom used, it says what it's doing in the status line while running through matches: "Changed match 1/2 · on to the next: . changes it, n skips it" after a change, "… · no other match" when there's none, and "Skipped to match 2/2 · . changes it, n skips again" after `n`; any key but `.` and `n` ends that, as with `f`. Without an operator, `gn` selects the match, as Vim's does, with the search as the selection's filter, so only it ("The match selected · an operator changes it").
  - **Clearing the matches:** `/` and Enter, an empty search having nothing to match (rather than Vim's repeating the last search, which `n` does), as well as `:noh` and `, s c` (`, S c` since November 2026). Escape at the prompt leaves them. Up and Down at the `/` prompt recall earlier searches, kept apart from the `:` line's history, as Vim keeps them (decided November 2026); for the session, as the `:` line's is.
  - **`*` and `#`** search for the exact pitch under the cursor (C3, not every C, as Vim's `*` takes the whole word; `f` is for any octave), or on a controller's row of the event list that controller.
  - **Matches follow edits:** the query is kept, not a list of events, so the matches and `match 3/24` are as the song is after each edit.
  - **The arrangement:** the cursor's track only, `n` and `N` going to the next bar and the one before holding a match, as `f` does, without highlighting for now.
  - **As built:** `n` and `N` go round past the ends, as Vim's do, saying so ("Past the last match, round to the first"), and keep to the search's way, as Vim's do, so after `#` `n` goes back; `/`, `n`, `N`, `*` and `#` are jumps, which `''` goes back from. After an operator, `n` takes the range up to the match, not it, as Vim's `dn` does, and `N` from it. The status line shows the search and where the cursor is among its matches (`/A1 match 1/2`, or `2 matches` off them; in the arrangement by bars, `bar 1/2 with matches`). In the piano roll `*` takes the cursor's pitch, the note's when it's on one; in the arrangement there's no note to take. A `#` straight after a find's letter is its sharp (`fc#`), so a search back for the pitch there needs another key between. Matches are drawn in a colour of their own, the theme's `match` (decided November 2026): a matching note outlined in it in the piano roll, over the current note's and a selection's colours alike, and a matching row's text in it in the event list, as Vim colours matched text; noticeable without being distracting. A matching note's velocity bar in the lane is in it too, whatever the query matched the note by, so the bar and the note above it always agree. Matching controllers are to be highlighted in the lane too, each event apart, since they don't belong to notes, once the lane shows controllers (noted November 2026, for the controller lane's work).
  - **Queries:** terms separated by spaces, all of which must match: a pitch (`C1`, `F#3`), or a pitch class with no octave (`C`, any octave, as `f`), or pitches above or below one (`>A3`, `<=C4`) or in a range (`A3-A5`, both ends included, either way round; a `-` before a letter marks the range, so `C-1-G2` is C-1 to G2, and an octave is needed at each end) (decided November 2026); `vel<60`, `vel>110`, `vel=100`, `vel=60-90`; `len<1/32`, `len>1/4`, in note fractions turned into ticks as the search runs; a controller, `cc1`, with leading zeros or without (`cc01`), and with a value or a comparison (`cc1=127`, `cc64>63`, `cc7=20-40`); `bend`. Drum-map names (`/kick`) wait for drum maps.

**Leader key and hint menu**

Less frequent commands live behind a leader key, as in Doom Emacs: press the leader (comma in Normal and Visual modes, leaving Space for play/stop; Ctrl-Space as an alternative leader in Insert mode, milestone 8, where comma is typed; in Normal mode `Ctrl-Space` plays from the cursor, as decided in milestone 6), then a short mnemonic sequence. After a brief pause a hint menu appears at the bottom of the window listing the next available keys and what they do, so commands are discoverable without being memorised first.

| Sequence | Command |
| --- | --- |
| `, f s` / `, f o` | File: save / open |
| `, t n` / `, t d` | Track: new / delete |
| `, x i` / `, x T` | Transform: invert / transpose in key |
| `, v a` / `, v p` | View: arrangement / piano roll |
| `, p o` | Ports: choose output for this track |
| `, l` … | Default note length (see Default note length) |
| `, T s` | Scale lock on/off (proposed; see To decide) |

The most frequent operations stay on single keys for speed and muscle memory; the leader tree holds everything else. Both are defined in the keymap file, and hint labels come from the same definitions.

**After an operator too (decided October 2026).** Pausing after an operator (`d`, `y`, and later `>`, `q`, `^` and the rest) shows the ranges and objects it takes, each with what it would do with that operator in the current view, so the grammar is learned while using it. The keys that only move aren't listed. In the piano roll, for example:

```
d  delete
  ]b  to the next bar line      ib  this bar's notes
  ]s  to the next section       ab  this bar, closing the gap
  G   to the end of the song    in  this note
```

It comes with the leader's hint menu in milestone 6.

**As built in milestone 6 (October 2026).** The leader is a setting, `leader` (`,`), and `<leader>` a key in bindings, matched to the setting as keys are typed (in Normal, Visual and operator-pending mode), rather than fixed when a binding is read as Vim's `mapleader` is: the built-in `modalrc` runs before a user's, so a user's new leader would otherwise miss the built-in leader bindings. Keys that start longer bindings take a title for the menu with `ngroup KEYS "TITLE"` (and `vgroup` and the rest), written by `write-config` with the bindings. The hint menu covers the whole keymap, not only the leader (decided October 2026): after `hintdelay` (400 ms; `hints` turns it off), a panel above the status line shows the keys typed and their group's title, then each key that can follow, by its title (a binding's hint, or its command's title, `{count}` written N), in columns after Doom Emacs's (decided October 2026, after use): six rows down and then across, each column as wide as what's in it so the menu gathers at the left, more rows only when the columns don't fit across, each key right-aligned in its own colour (`hint-key`, green), a colon, then its title, and groups marked `+` in a colour of their own (`hint-group`, purple); keys go in order with named keys first, then other characters, then letters ignoring case, `t` before `T`. Keys bound to one command show together, characters first and plain arrows drawn as arrows, as `h/←` and, after an operator, `l/→` (decided October 2026, after use). It offers only what does something where the cursor is: each command says where it does something (`where`: the arrangement's tracks, its strip, the piano roll, the event list), kept in one table in the workspace since views run commands others describe, and a test runs every binding offered in each place to check none says it isn't there. It stays as keys go deeper and goes when a command runs or Escape gives them up. After an operator, it lists the doubled operator (the cursor's bar), the objects and the ranges, each command once by its shortest key, with what the view says each would take (`describeRange`), leaving out the keys that only move. The leader holds for now what was on comma (`, n`, `, t Space`, `, t a`) and `, v a` / `, v p` / `, v e` for the views; `, f` for the file commands waits, since those are registered by the program after the built-in bindings are read. `<leader><leader>` is kept free for a command used often enough to earn it. `Ctrl-Space` stays play-from-the-cursor in Normal mode, being a leader only in Insert mode (milestone 8).

**One command per meaning (decided October 2026).** A command does one thing, named for it, rather than meaning different things in different views: keys can be bound to several commands, each doing something in places of its own, and mean the one that does something where the cursor is, the later bound where more than one does, so a user's binding still overrides a built-in one. So `J` is `join` (since November 2026 `section-join`, with the strip's other commands named for sections: `section-insert-before` and `-after`, `section-move-earlier` and `-later`, `section-rename-strip`, and `x`'s partner `event-yank`) on the section strip and `octave-down` in the piano roll; `=` `-` `+` `_` are `note-lengthen` / `note-shorten` (and `-fine`) in the piano roll, `section-lengthen` / `section-shorten` on the strip and the `field-` commands in the event list; `Ctrl-A` / `Ctrl-X` are `velocity-up` / `velocity-down`, `section-lengthen` / `section-shorten` and `number-increase` / `number-decrease`; and `Tab` / `Shift-Tab` are `cursor-note-next` / `-previous` in the piano roll and `bar-events-next` / `-previous` on the arrangement's tracks. The palette, `:` and the list of keys name each as itself. Keys none of whose commands does something here say where they do: "= is for the section strip, the piano roll and the event list".

**The list of keys (decided October 2026).** The hint menu shows only what follows keys already typed, so single keys such as `G` never appear in it; `, ?` (`keys-show`) lists every binding that does something where the cursor is, over the view, in groups: the built-in `modalrc`'s sections, each started by `keysection "TITLE"` (a command-file command, its section holding for that file's bindings), in the file's order, with "After an operator" for the objects and "Other keys" for bindings outside any section. Each command shows once with all its keys, as in the hint menu, in the group of its first binding. Commands that do the same where the cursor is, with the same title, show as one (decided October 2026, after use: the event list's `+/=/<C-a> : Step up`), and a binding without a hint isn't listed beside one of its command that has one, so the built-in keypad and other keyboard layouts' keys for bigger text are bound without hints and the list shows `<C-+>` alone. `q`, Escape or `?` closes it, `j` / `k` (or the arrows and Page Down and Up) turn its pages when the window doesn't hold it, and other keys do nothing, so a stray key can't change the song. `, h` is kept for a help group, should one come. Searching it is left to the command palette.

**The leader's groups for the song's parts (decided November 2026, in the key map review).** Lower case for the song's building blocks, each a group: `, b` Bars (`, b d` and `, b i` on every track), `, s` Sections, from any view on the cursor's section (`, s r` rename, `, s i` and `, s a` insert before and after, `, s j` join, `, s s` start one at the cursor's bar line, `, s l` one from the label before), and `, t` kept for Tracks; Select moved to `, S`, a step towards something else rather than a part of the song, and `v` with an object selecting most things without it. The strip keeps its single keys, as their own commands named for it (`section-join-strip`, `section-insert-before-strip` and `-after-strip`, `section-rename-strip`), so `J`, `i`, `a` and `c` stay the strip's. A new section's name is asked first, with "Section N" to edit, and the section goes in named as one step, Escape putting none in (decided after use, `, s a` having renamed the section the cursor was in): `i` and `a` on the strip, `, s i`, `, s a` and `, s s`, and `:section-split` with no name; inserting moves the cursor to the new section.

**The list of keys regrouped (decided November 2026, in milestone 6's key map review, after use).** Each group is kept whole in one column: a group that doesn't fit below the one before starts the next column (or page), leaving a gap, and only a group longer than a whole column goes on in the next, its title repeated as "(continued)"; a group that broad is a sign it should be split. The groups were made narrower to suit, in this order: moving the cursor; moving in time (with the arrangement's `Tab`); finding and searching (`f`, `/`, `n`, `*`); pitch in the piano roll; tracks; marks; views (the `g` and `, v` keys, zooming and `zf`); scrolling; the section strip (with `i`, `a` and `c`); the grid and default note (with `, T a`); adding and moving notes (`o`, the `Alt` moves and the end keys); editing fields (with the inspector's `e`); deleting, yanking and putting; operators (with `!`); undo, repeat and macros; after an operator; Visual mode; selecting (`gv`, `gn` and `, s`); the transforms, split into pitch and time, velocity, chords and controllers, and pedalling; playing (transport keys only); text size; the command line; and help (`, ?`). `v` is titled "Visual columns", beside "Visual rows" and "Visual box". Titles leave out commands' default values ("Lift velocities", not "Lift velocities (25%)"), which are only some of their options and which each asks for or shows when run. The toggles moved to `, T` (see Toggles), keeping `, t` for the tracks.

**The hint menu after an operator, in columns (decided November 2026, in the key map review; built).** Objects and motions are told apart: an "Objects" group, the operator's own key first (`d`, for `dd`, being an object: this track's notes in the bar), in one or two columns, and a "Motions" group in as many columns as it needs, a faint vertical rule between them and a heading over each, each group filling its columns top to bottom; in a window too narrow for that, one column with the two headings. The list of keys keeps its own groups.

**Command palette (decided October 2026)**

Three ways to reach any action: keys, for speed and muscle memory; the hint menu, for browsing by category; and the command palette, a fuzzy search for when you roughly know what you want but not where it lives or how it's bound.

| Key | Effect |
| --- | --- |
| `Ctrl-p` | Open the palette, in any mode (Insert mode to decide) |
| `, :` | The same from the leader, like Doom Emacs's `SPC :` |
| `Ctrl-n` / `Ctrl-p`, or `Ctrl-j` / `Ctrl-k` | Move down / up the list, inside the palette |
| `Enter` | Run the highlighted item |
| `Tab` | Copy the command to the command line to edit before running it |
| `Esc` | Close |

- A box opens at the top of the window, with the filtered list beneath it, updating as you type.
- **Matching:** fuzzy ("vcomp" matches "Velocity compress"), searching descriptions and aliases too, so "crescendo" finds "Velocity ramp" and "pedal" finds the sustain tools. Frequently and recently used commands rank higher, and the ranking is kept between sessions. Commands that don't apply in the current view rank lower or are dimmed, and the palette shows what a command will act on, e.g. "selection: 4 bars, Bass".
- **Teaching the bindings:** each row shows the command's title, description and key or leader sequence; after a command runs from the palette, the status line briefly shows its binding ("Also: , x c").
- **A front end to the command line:** every action is a `:` command, so `Enter` runs it with its defaults or prompts for its parameters with the defaults filled in, and `Tab` puts the whole command on the command line (`:vel compress 50% window=1bar`). Commands run from the palette repeat with `.` and record in macros like any other.
- **Searching more than commands:** a first character changes what's searched. `@` sections (`Enter` jumps there, or during playback cues it, with `Shift-Enter` to jump at once); `#` tracks (switch to the track in the current view); `'` markers and marks (jump to it); `?` settings, with their current values (edit the setting). For example `Ctrl-p @br Enter` jumps to the Bridge, and `Ctrl-p ?metro` shows the metronome's settings. Results show useful context: a section's bar range, meter and takes, a track's port and channel, a marker's position.
- All of it comes from the command registry (see Architecture).
- **As built in milestone 6 (decided October 2026).** In three parts: the commands first, then ranking by use kept between sessions, then the prefixes. It opens at the bottom, where the rest of the typing is (decided October 2026, rather than at the top): its line in place of the status line, labelled "Command: " (from Visual mode "Command on bars 2–4 on every track: ", running the command on the selection as `:` does), and the list above it, the best match nearest the line, each row the command's title, its keys in the hint menu's colour and its description dimmed, the chosen row in the cursor's colours, commands that do nothing here dimmed and last. Up and `Ctrl-p` / `Ctrl-k` go up the list, away from the line, Down and `Ctrl-n` / `Ctrl-j` down; at the `:` prompt those keys go through its history, as in Vim. Enter runs the chosen command, or for one that takes arguments, even ones it can do without, puts it on the `:` prompt with their hint showing (decided after use, so `Bar insert` doesn't quietly insert a bar of the meter there when a meter could have been given), with its choices showing too for one that must have one; Tab always puts it there; each row shows its arguments dimmed after its title (`Bar insert [N] [METER]`); at the `:` prompt, once a command and a space are typed, its arguments not yet typed show dimmed after the line, each going as it's typed; after one runs, the status line shows its keys ("Also: zi"). It matches keys too, as typed (`zh`, `(`, `J`), a key that's exactly what's typed first and one starting with it after the title and word matches, for finding what a remembered key does (decided after use). It searches the commands that run from Normal mode, not the objects or the prompt's own, nor those for config files alone (binding keys and naming their groups: `nmap`, `cgroup`, `keysection` and the like, marked `palette = false` as Emacs marks commands not for M-x; `set`, `highlight` and `write-config` stay). Nothing is chosen until something's typed (the best match) or Up or Down is pressed, so Enter can't run the first command by chance; once the ranking by use comes (7b), the command ranked first by how recently and often it's been run is chosen at once, so `Ctrl-p` Enter runs it again (decided after use). From Visual mode a command runs as its keys would there: an operator on the selection, Cut at edges on or off for it, a command taking a range on it; Escape goes back to the selection.
- **The prefixes, as built (October 2026).** `@` lists the sections with their bars and meter, Enter going to a section's start (cueing it while playing waits for cueing, milestone 8); `#` the tracks, with their number, port and channel, Enter going to the track, in the arrangement the cursor moving to it and in the piano roll and the event list the view switching to it; `'` the markers, with where they are, Enter going there (marks join them in milestone 6's marks step); `?` the settings, with their values and descriptions, Enter putting `set NAME=VALUE` on the `:` prompt to change, so nothing changes until it's run. They match as the commands do, by name and then by what's beside it; but sections, tracks and markers are listed from the top down in song order, as the arrangement shows them, rather than ranked from the line up (decided after use), and among equally good matches keep that order. Up, Down, Page Up, Page Down, Home and End move the way the list looks, Home to its top and End to its bottom; the list scrolls to keep the chosen row in view, a ▲ or ▼ at the side where there are more.
- **Ranking by use, as built (October 2026).** Each command run from the palette is remembered with how often and when it was last run; its rank is how often, the recent counting for more (within the hour eight times as much as over a month ago, halving at a day, a week and a month), and within each kind of match the higher ranked come first. Enter counts as running it, Tab doesn't. `:palette-forget` forgets. It's kept, with the meters typed, in `remembered`, a plain-text file in the state directory (`%LOCALAPPDATA%\Modal`, `$XDG_STATE_HOME/modal`), apart from the config directory, which is for what the user writes; the program reads it at start and writes it after each change, so nothing waits for Modal to close.
- **Meters offered (decided October 2026, for the state file with the palette's ranking):** the built-in ones and those the user has chosen before that weren't among them, typed at `:bar-insert` or in the event list's meter field, as one list in order by denominator then numerator, so the one wanted can be found by scanning. Not the song's own, which were first offered too, but include the remainder bars sections leave, of no use there (decided after use). `crash.log` moved to the state directory with them, being written by Modal rather than the user.

## Input and recording

**Step 8.2's choices (decided 10 November 2026).** Each track's Input column goes after Output port, so the two ports read together. Input activity shows on the status line, a light and the last note, so it's seen in every view, rather than only on the armed tracks' buttons in Tracks. Switching Thru everywhere is the machine's, a `thru` setting with `, T t`, since it's for the keyboard in use (local control) rather than the song.

**Recording in the GUI (decided November 2026, for milestone 8).** Settled before the milestone's first step, as the schedule asks:

- **Inputs are a `modalrc` setting,** `inputs`, every input port found by default, since ports differ between machines and a song's list would break when it moves to another until port aliases exist. Each track's own input, saved with the song, follows later in the milestone, as the design has always allowed. Modal's own ports are left out of the inputs, as listening to them would send Thru round in a loop.
- **Arming is a toggle per track,** like mute and solo, rather than arming one disarming the others, since recording several tracks at once (the same take on each channel, for layering) is wanted, and `V` already gives a way to change several. A track left armed by mistake is easy to miss, though, as has happened in use with other sequencers; so arming one while others are armed names them in the status line, without refusing, and starting to record onto several names them all.
- **`R` records from the play-from marker,** as Space plays from it, so the record point is the same marker playback starts from and rewind behaves the same; Space stops. A single key, as recording is frequent; `Ctrl-r` is redo and the function keys are kept for cue slots. Vim's `R` (Replace mode) has no planned use in Modal, whose Insert mode is step entry.
- **The `, r` group holds recording:** `a` arm and `t` Thru, and later the replace/overdub mode and the count-in. `, t a` was left for adding tracks, as the design lists add among the `, t` commands to come.
- **Replace or overdub is a song setting,** saved with it like the count-in and metronome, since it's part of how a song is being worked on; the status line shows it, as forgetting which is set loses material.
- **Buttons without headings, their letters always shown** (decided November 2026, with Arm and Thru added): the button columns had headings wider than the buttons, and two more would make the table wide. Dropping the headings lets the buttons sit close together, and showing each letter grey when off, in place of a dash, says what each is to anyone who has used a sequencer. So nothing is lost for those who haven't, the inspector says first what the column under the cursor is, as a tooltip would, which also makes the other columns more discoverable.
- **Thru on a track not armed is unfilled** (decided November 2026, to try in use): Thru is on for new tracks, so most rows would otherwise show a filled `T` that does nothing until the track is armed. With letters grey when off, dimming it would look like off, so it shows its letter in its colour, unfilled, and filled once the track is armed.
- **Arm is bright red, Mute a lighter pink** (decided November 2026, after use): Arm in orange sat too close to Thru's amber. Record is red on most hardware and software, and an armed track should stand out, so Arm took a bright red and Mute, which had been red, moved lighter so the two stay apart.
- **The Tracks inspector shows only what's under the cursor** (decided November 2026, after use): it had ended with the track's name, which moved about from row to row as the fields above it changed, and the bar above already names the track. The name is about the track rather than the column, so it went.
- **Three places, three subjects** (decided November 2026, after use): the bars and inspector had grown to repeat each other (the track in Tracks' status line, the section top and bottom, a position in both the inspector and the status line), and a section name at the bottom could be the cursor's or the playhead's. Now the bar at the top is where the cursor is (its track, section and bars, position, time and meter), the inspector what's under it, and the status line the transport, settings, file and messages. Stopped, the status line shows the play-from marker, with ■, and playing, the playhead counting on from it, with ▶, as a hardware sequencer's counter does, so where Space will start is always in view; the tempo goes with it, at the marker or playhead, rather than at the cursor. The transport has a fixed place straight after the mode, with messages after it, since a message replacing it would hide the playhead while playing until a key. The meter shows in both places, the cursor's in the top bar and the transport's in the status line, told apart by the top bar's labels and the transport's glyph. Fields are padded to the song's widest, and what varies goes at an end, so nothing jumps as values change. The Tracks view has no timeline, so it shows no place in time, the cursor's time included (which it had shown since October 2026 for where the cursor would land on changing view); the arrangement's and section's inspectors lost Position and Meter to the bar. Where the top bar is too narrow, the track's setup goes first, then the section's bars and the section, and never the track or the cursor's place; pairs in the bars are three spaces apart rather than five, to fit more.
- **Prompts off the status line, the palette top down, completion a popup** (decided November 2026, after use): with the transport on the status line, a prompt over it would hide the playhead while typing, and typing a filter in the middle of the status line, with the matches over at the left, looked odd. So every prompt gets a row of its own above it. The palette follows Doom Emacs's M-x, its line at the top and the best match first beneath it, reading down as every other list does and with Down going to the next as `j` does; it costs the line being some way up, but at a fixed height it's always in the same place. Completion at the `:` prompt is lighter than the palette, mostly short choices, so its matches became a small popup over the word, as the Tracks view's port list is, rather than a full-width panel that would move the line up for a quick `:w`; the first match is next to the line there too.
- **The grid with the settings, the new note in the inspector** (decided November 2026, after use): the piano roll's top bar had the grid and the new note's length and velocity (`grid v100`), which crowded out the track and section once it gave the cursor's place. The new note is the cursor's potential note, what `o` would add where it is, so it went to the inspector's right, stacked and spelt out (`Length: grid`, `Velocity: 100`); the grid is the view's, so it went to the status line with Rewind and the other settings.
- **A wider gap before Quantise** (decided November 2026, after use): Time offset's values align on the right and Quantise's on the left, so with one blank cell between them they ran together, where narrower numbers such as MSB and LSB have room to spare. Time offset keeps two blank cells after it.

**Acknowledged input replacement (decided 10 November 2026, after review).** Closing an input while its note or pedal is held prevents the release from arriving, and reusing its numeric InputId can let another device release the old state. Close the old producers first, then queue an engine input reset and await its acknowledgement asynchronously before opening replacements. Drain again inside the reset command: a final callback may have queued input after the engine's normal input pass but before the producer closed. Release Thru notes and pedals only, without stopping playback or issuing a global controller reset. Retry a full command queue from a short GUI deadline and use the latest setting once acknowledged. Keep the current all-ports reopening behaviour rather than introducing selective port replacement in this fix.

### Settled choices from the former checklist

**Milestones 1–2: engine and recording**

- Scheduler look-ahead. The engine sends each event itself at its exact time. Since the playback plan already holds every event's send time, there is no window to prepare: the engine sends whatever is due when it wakes, and any edit, mute or tempo change during playback applies to every event not yet sent. If milestone 1's loopback measurements show too much jitter on a platform (p99 send lateness or loopback jitter above about 1 ms), that backend switches to OS-timestamped delivery (around 50 ms ahead, recalled on stop or edit). The MIDI interface is designed to allow either. Windows measured well under the threshold (see Measured timing, Windows); Linux is still to be measured (below).
- Panic key: `Ctrl-.`.
- Record input: all MIDI inputs by default, optional per-track input. MIDI thru on by default, changeable.
- Milestone 2's recording, pedal, metronome, export and tool decisions (October 2026): see Input and recording, Playback and recording behaviour, Metronome and count-in, Other files, Architecture, and Build and tooling.

## Decisions and open questions

- Most important from SPG: a fast, stable key-binding model that builds muscle memory.
- Vim-like modal editing, plus a Doom Emacs-style leader key with a hint menu.
- Leader key is `,`, with Ctrl-Space as an alternative leader in Insert mode (milestone 11; in Normal mode it plays from the cursor, decided in milestone 6); Space stays play/stop.
- `q` is quantise; macros move to another key (`Q` proposed).
- 960 PPQN, fixed internally, matching the common DAW editing resolution; kept as one constant so it can be raised later.
- Arrangement is the home view; piano roll for editing a track.
- Patterns are a nice-to-have, not version 1.
- In-process plugin hosting is wanted eventually.
- Configuration is a Vim-style command file, sharing the `:` command language.
- Sections are the song's structure and markers are bookmarks (October 2026); see Sections and labels. Markers renamed labels (November 2026).
- The velocity operator is `^`, since `v` is Visual mode, and `!` is the general transform operator (October 2026).
- Vim uses `,` to repeat an `f` search backwards, `,` being the leader here: `f` and `F` repeat a find instead, as Doom Emacs's evil-snipe does (decided October 2026; changed November 2026 to `;` the same way and `Alt-;` the other). The scale-lock key is still to choose (see To decide, Later milestones).
- Piano roll navigation, grid and default note length (October 2026): a crosshair cursor; `{` / `}` keep the position in the bar, with bar lines on `[b` / `]b` (`[[` / `]]` until October 2026); `gg` / `G` go to the start and end of the track; pitch motions and scale lock; Alt plus a motion moves notes; a per-track grid and default note length; the piano roll shows pages of whole bars. See Editing grammar and Views.
- Licence: GPL-3.0-or-later (October 2026), which keeps forks open and allows JUCE's AGPLv3 terms if plugins are hosted with it. The repository is public on GitHub; third-party licences are in `licenses/`, and every C++ file carries an SPDX line.
- The name is Modal (October 2026), settled with the repository public, knowing that Modal Electronics (synthesisers) and Modal Labs (cloud computing) use the name too.
- Language: C++20 throughout. C# was considered, but GC pauses in the real-time engine, weak Linux MIDI support in .NET libraries, and C++-only plugin hosting all favour C++, as does day-to-day familiarity.

### Performance considerations from the November 2026 review

The review identified bounded, round-robin processing of input so controller floods cannot hold up playback; off-thread Windows SysEx sending because WinMM blocks; a note-off heap if polyphony measurements justify it; reducing the command-line tools' 20–50 ms keyboard polling; separating core/UI/platform/SDL test executables; and measuring `Song::updateEvents` copying track events and full playback-plan compilation after each edit before deciding whether to skip or coalesce rebuilds. By this documentation cleanup, transform definitions were centralised, workspace state was gathered and its implementation split by responsibility, undo used named/tagged view state, and command outcomes were separated from warning severity so warnings no longer failed macros.

## Hardening before further GUI recording

**Retain the members of a moved selection (decided 10 November 2026, after use).** A moved Visual area was re-evaluated against the song after every move, so a neighbour newly inside it became selected and moved on the next Alt-arrow. Preserve the originally moved notes at their new starts and pitches instead. This is transient editor state, shared immutably by the selection and its gv recall; it adds no song-format identity fields. Explicit cursor extension, another object or a change of Visual kind deliberately replaces that membership. Content operators use the same members as moving and drawing; time operations retain their existing range semantics. Fix this before the approved input-management extraction and bounded/fair input work, and complete all three before step 8.2. Broader editor refactoring remains a separate decision.

**One owner for input lifecycle and IDs (decided 10 November 2026).** Extract `MidiInputSession` from the GUI executable into the platform library before adding per-track input selection. Port ownership, the active name-to-ID mapping and reset acknowledgement must agree; putting them behind one interface prevents future chooser/filter code from inventing a different map. Let the caller provide milliseconds and poll a deadline, avoiding an SDL dependency. Inject port enumeration and opening for hardware-free tests, with port destruction explicitly joining callbacks. Preserve all-ports replacement, matching, limits and reporting; selective replacement and hotplug remain separate work.

**Finite input snapshots and fair service (decided 10 November 2026).** An input producer could refill its queue while the engine drained it, indefinitely delaying later ports, transport and playback. Capture finite queue lengths and normally service 32 complete messages per pass in quanta of eight per port. Finish captured input before transport changes so old input keeps its recording play/tick/time, and finish each SysEx before yielding so no framing or stamp state has to span transport changes. This deliberately permits a transport drain up to the captured queue capacities; incoming traffic cannot extend it. The reset command still captures any final callbacks after close. Bound tuning needs hardware measurements.

**Keep collecting a bounded backlog (decided 10 November 2026).** With work spread over engine passes, a one-off GUI settle timer could expire before a burst finished, leaving later stamped batches uncollected. Track accepted and processed message counts atomically; publish processed counts after outgoing chunks. The GUI checks pending work before collecting, repeats its timer until processing is complete, then collects the final published batch before returning to idle. **Bounds around snapped selection members (decided 10 November 2026).** Grid moves can shift an off-grid note by less than a note already on the grid. Moving the rectangle by the first note's delta could then leave another retained note exactly outside its end, so moving would still take it but deletion, yanking or a colon transform would miss it. Extend the span around the retained starts, to the grid line after the last where needed, while retaining explicit membership so neighbours inside the expanded span remain untouched. Regressions first reproduced all three editing paths at 960 and 96 PPQN.
